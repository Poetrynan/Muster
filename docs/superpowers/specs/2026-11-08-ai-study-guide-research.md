# Muster AI 学习导读：调研与设计建议

日期：2026-11-08（Asia/Singapore）。状态：调研完成，开发方案待采用；本轮未修改应用代码。

## 1. 决策摘要

将 AI 主入口定位为“课程学习导读”：学生选择课程与周次，不必编写提示词，即可得到有来源、可执行、可追踪的行动卡片。
不将连续聊天作为下一版主功能，不扩大本次尚未提交的 CourseChat 改造。将来的卡片内解释是可选的后续实验，不与基础导读捆绑。
优先把课程动态、考核结构和截止事项接成可靠工作流；不是靠减少聊天控件就能形成差异化。

“无需向量检索”限定为：单课程、明确周次、已结构化且能放入预算的资料集合。它不代表无需选择上下文，也不代表对整学期 PDF 语义查询永远不需要检索。

## 2. 证据与边界

### 已核验的一手资料

1. Google，NotebookLM 入门指南，2024-10-18：已有来源问答、原文引用、导读、时间线等能力。说明“卡片而非聊天”本身不是技术护城河。用于证明能力已存在，不用于声称当前价格、限额或最新产品命名。
   https://blog.google/innovation-and-ai/products/notebooklm-beginner-tips/
2. Anthropic，Contextual Retrieval，2024-09-19：有限资料集合可直接放入上下文，更大资料库再考虑检索。其 200k token 示例不是 Muster 或所有 BYOK 模型的预算。
   https://www.anthropic.com/research/contextual-retrieval
3. Anthropic，Context engineering，2025-09-29：挑选足够且高信号的上下文，而非盲目增加长度。
   https://www.anthropic.com/research/effective-context-engineering-for-ai-agents
4. Microsoft，Human-AI Interaction，2019-03-05：明确能力边界，提供相关信息、原因、纠错和降级入口。支持展示资料覆盖与可解释建议，而不是空白输入框诱导无限能力预期。
   https://www.microsoft.com/en-us/research/articles/guidelines-for-human-ai-interaction-eighteen-best-practices-for-human-centered-ai-design/
5. EEF：计划、监控、评估是自我调节学习的重要环节。主要证据来自学校教育，不能据此宣称 Muster 能提升大学成绩，更不能套用页面的平均进步月数。
   https://educationendowmentfoundation.org.uk/education-evidence/teaching-learning-toolkit/metacognition-and-self-regulation
6. Monash TeachHQ：AI 使用要求按考核任务说明。产品可展示这些要求的原文入口，不能推定某一课程允许 AI，也不提供默认代写作业流程。
   https://www.monash.edu/learning-teaching/TeachHQ/Teaching-practices/artificial-intelligence/AI-statements

### 尚未证明的产品假设

- 学生比起聊天，更愿意定期查看并完成导读任务。
- 节省手动收集资料的时间，足以抵消设置自有 API 的成本。
- 从公告和日程生成建议，能稳定降低遗漏，而不增加无用提醒。

上述需要真实学生测试；点赞数不是活跃用户数，也不是效果证据。本轮未访谈用户、未调用付费模型、未读取私人课程缓存。

## 4. 产品界面

### 首页：今天先做什么

不增加大型独立 AI 聊天页面。展示最多 3 项近期行动，每项包含：
- 动作：打开哪个任务/资料；
- 原因：明确截止时间、占比或新公告变化；
- 状态：未开始/用户已完成/待评分等分开表达；
- 来源：原文片段与打开原始页面；
- 标签：确定事实 / 学习建议 / 数据不足。

规则引擎可离线完成的日期、占比、状态、排序基础信息，无 API key 也可见。AI 是生成解释与计划的增强层，而不是显示真实事实的前提。

### 课程页：本周导读

顶部：课程选择、所选教学周、最近同步时间、资料覆盖（如 3 份已读正文/2 份仅标题）。不要由用户手输指令。
依次呈现：
1. 本周概览：按大纲与日程明确描述主题。只有标题时只列主题线索，不生成假知识点。
2. 优先行动：最多 3 项，可打开来源、加入计划。
3. 复习计划：先给 1 个低负担参数“本周可投入几小时”，提供可编辑默认值；建议时长明确是估计。
4. 最新变化：新的/更改的截止事项、公告和资料；冲突保留双方原文，提示待确认。
5. 依据：按卡片展开，不使用一整页重复警告或模型自评高置信度徽章。

卡片内可提供“解释这项建议”“缩短计划”这类有固定输入范围的动作；首版优先做“查看依据”和“调整可用时间”。不先做多轮记忆。

### 完成与反馈

学习任务勾选不等于已提交 Moodle 作业；学生点击打开资料不等于已学会。保留稳定 taskId、学生修改和完成记录；重新生成只提出差异，不悄悄重置进度。
支持“来源有误/建议没帮助”，不得只用是否勾选推断推荐准确性。

## 5. 工程方案

流水线：同步快照 → 课程/周次选择 → 事实与规则计算 → 有预算的证据包 → LLM 解释/计划 → 结构校验与事实核对 → 导读卡片/Markdown 回退 → 缓存与行动记录。

事实计算与建议生成分离：
- 程序算：时区后的截止时间、剩余天数、考核占比、可确认的成绩、优先级基础等级。
- 模型写：事实的简洁解释、基于所给资料的学习顺序、在可用时间内的任务拆分。
- 未知保留未知：best-N、warmup、hurdle、多个考核结构适用范围不明时，不出“已经通过”等确定结论。
- 不能只校验 sourceId 存在；还要核对字段、时间、数字与证据是否相符。解释类语义仍需人工抽查，不能宣称消灭幻觉。

### 建议的数据契约（待实现）

- SourceRecord：id、accountScope、courseId、weekId、kind、url、locator、excerpt、contentHash、syncedAt、coverage。
- FactRecord：id、field、value、unit、sourceIds、status（verified/estimated/conflicting/unknown）。
- GuideCard：id、kind、title、explanation、factIds、sourceIds、actionTarget、suggestedMinutes。
- GuideArtifact：accountScope、courseId、weekId、schemaVersion、promptVersion、inputHash、model、language、generatedAt、status、cards、markdown、coverage。
- TaskProgress：stableTaskId、sourceId、taskKind、courseId、weekId、done、userEdited、updatedAt。

schemaVersion/promptVersion 必须参与缓存。账号绑定遵循现有 store 的缓存归属约束，不能跨用户复用结果。

### 上下文选择

优先：本周明确关联的学习目标、未来 7 天截止与最近变更 → 相关考核说明 → 本周公告 → 其他补充。
教学周必须来自课程日历；假期、跨学期 Thesis、未知周不得按自然周自动猜。允许选择周次；无周次资料可纳入“全课程相关资料”，并在覆盖面板披露。
固定要求和预算优先保留。超预算按整条 source 剔除并记录 omittedSourceIds，不半截裁断关键日期或条款。暂保守沿用小预算，再按供应商配置扩展；字符不等于 token。

### 输出与流式

先稳定显示规则事实卡；AI 的正文以流式纯文本出现，完成并校验后升级为可操作卡片。不要把未闭合 JSON 逐块变为可执行任务，也不要暴露机器附录。
默认继续兼容 OpenAI-compatible / Anthropic / Custom 接口，不强制所有供应商支持同一种 strict JSON schema。可选能力支持时使用供应商结构化输出；统一客户端仍需验证和回退。
请求捕获 course/week/inputHash，后返回的旧请求只能写回自己的 artifact。取消应中止传输而不只是隐藏更新。

### 降级矩阵

| 情况 | 应显示什么 | 不可出现 |
|---|---|---|
| 正文正常，附录 JSON 错 | 正文 + 来源面板 + “未生成结构卡” | 全部丢弃或空任务被误认为没有任务 |
| 请求失败/429/超时 | 原始事实 + 上次成功导读（标旧）+ 可重试 | 覆盖上次成功产物 |
| 流中途断开 | 部分正文（标未完成），不生成可执行卡 | 标成生成成功 |
| 来源缺失或互相矛盾 | 未知/冲突，展示原文入口 | 伪造日期或仅按“最新”强行裁决 |
| 只有推理/只有 JSON/空内容 | 可校验部分或基础事实，附明确状态 | 把推理当最终答案；空白成功 |
| 无 key/离线 | 原始事实、规则优先事项、已缓存导读 | 把核心学习信息锁在 API 配置后面 |

### 资料与隐私边界

API 设置应说明：配置和缓存保存在本机，但生成时选中的上下文会发往用户配置的供应商。生成前可查看发送范围，默认去掉名字、邮箱、学号和无关反馈，不上传密码/令牌。成绩只在相关任务需要时选择性发送。
不自动上传整门课 PDF；也不推定用户可向第三方传送全部教学材料。

## 7. 验证与发布门槛（目标，尚未测得）

离线黄金集至少 40 个案例：普通周、无课周、考试周、Thesis 跨学期、空数据、中文长文、重复考核、公告冲突、隐藏成绩、warmup、hurdle、未知周次、坏 JSON、429、断流、请求乱序、账号切换。
- 确定性事实计算与来源归属：全部黄金集通过，新增虚构日期/分数必须阻止发布。
- 所有事实卡有存在且能定位的来源；语义“被来源支持”另行人工核对，不能用 ID 通过率冒充事实正确率。
- 所有故障注入场景始终保留基础事实；已有成功产物不被坏响应覆盖。
- 400px / 768px / 1280px、浅深主题、四语、键盘操作无横向溢出或关闭入口丢失。
- 单个范围生成一次有上限调用；相同输入回访不自动重复扣费；延迟、费用按供应商记录 p50/p95，不承诺未经测量的秒数。
- 先邀请 5–8 名学生完成“找本周最重要任务、解释理由、定位来源、调整计划”的任务，观察时间/误解/错误反馈，不以生成量或点赞数代替有效使用。

若确定性过滤加全文选择已能完成任务，不引入向量库。只有出现持续的语义漏召回或必要内容长期超预算，才在同一评测集对比：全量上下文、规则选择、关键词/FTS/BM25、向量混合；收益需覆盖成本、延迟和维护负担。

## 8. 简历表述

当前可诚实描述：围绕课程安排组织结构化上下文，支持流式摘要及行动/计划原型。不要提前声称有 PDF 正文理解、全模式可靠降级、严格单周筛选或逐条可核验引用。

0.5.0 验收后可写：针对按课程与周次组织的结构化教学信息，以确定性筛选和上下文编排生成带依据的学习导读；将事实计算与生成建议分离，并以纯文本、缓存和原始信息分层降级。

不能声称“消除幻觉”，不能在没有真实对照评测时写“更准/节省 X%/提高成绩”。
